# 输入路径修正与 HiRes 统计重建

后续第七轮已接上收缩、弱类型重估和OLS，见[HiRes收缩校准与官方对照](HiRes收缩校准与官方对照.md)。本文件保留第六轮状态。

2026-10-11，第六轮。已实际完成输入路径比较、完整基因范围的入口统计、冻结24基因的可检测性和两段差异统计，以及独立数值核对。所有计算在本机独立 R/Python 环境进行，原始研究文件与官方结果未修改；未登录服务器。

**本轮最大的进展是修正了比较时的表达输入。仍未完成完整 HiRes，也未达到官方全流程等价。** 对标目标是签名构建、比例估计和逐样本表达三个阶段都可复用；现在仅下游固定比例的几个数值阶段通过检查。

## Step1. 先纠正输入，而不是调整参数迎合结果

第五轮把 Job24 的 `Mixture-Adjusted` 导出作为核心 benchmark 的表达输入。该导出不能自动视为 HiRes 实际采用的表达表。根据原论文 S-mode 调整 signature、再对原始 mixture 估计比例的描述，结合旧数值调度线索，本轮同时比较原始 mixture、原始值下限设为1、Adjusted 导出三个候选，保留全部比较结果，未只报告最优候选。

原始表为 **17,040基因×120样本**；Adjusted 导出为 **15,885×120**，比原始表少1,155个基因。两者在冻结24基因集合上的表达尺度也不同，Adjusted 中有负数。缺失基因的具体导出过滤条件仍待追踪；不能简单把这些基因全部认定为没有表达。

同一官方固定比例、同一24基因、同一100次全局 bootstrap，对官方 group 输出的每类型 `log2(x+1)` MAE 再取中位数：

| 输入 | 实测误差 |
|---|---:|
| 第五轮：Adjusted 导出 | 0.905374 |
| 本轮：原始 mixture | 0.096167 |
| 这一指标的下降 | 89.38% |

这说明上一轮输入需要修正，不表示完整 HiRes 已有89%的准确率。Group 比较只是未过滤全局表达中间量的诊断；官方当前网页版的实际数据流还不能仅凭误差较小就断定。以后原始 mixture 是当前验证入口；旧结果原样保留，以便审阅这个纠错过程。

依据：[Newman et al. 2019](https://www.nature.com/articles/s41587-019-0114-2)，补充方法12.4.3；旧版本科学数值行为见[方法对照](原论文与HiRes实现逐步对照.md)。数据来源、SHA256和全部候选比较保存在 `input_space_audit/`。

## Step2. 完整基因范围的入口统计已独立跑通

[入口统计脚本](../scripts/R/reconstruct_hires_entry_statistics_20261011.R)按旧 native HiRes 调度重建：

1. 读取原始线性表达和固定的样本×类型比例表；检查顺序和满秩。
2. 对每个非全零基因，无放回抽取80/120样本，做30次 NNLS，保存系数中位数和重抽样标准差。
3. 用完整120样本残差、100个残差自由度和比例矩阵协方差，得到解析 t 检验的 p 值。
4. 每个细胞类型在完整17,040基因范围中对可检验项做 BH；不可检验项保持 NA。
5. 对存在 q<10⁻⁵ 的基因，按已定位的旧入口规则将其他 q>0.01 的类型标为1。

共17,040基因，58个全零基因保留不可检验 p 值；实际509,460次 NNLS。计算段约51.39秒。本轮冻结旧入口的2/3抽样规则；旧辅助 R 的 Group-mode 另有75%抽样、log空间汇总等差异，不能混用。这不是官方 Group-mode 的替代成品。

结果在 `entry_statistics_original_run1/`，包括中位数、标准差、原始p、BH q、worker q及RDS检查点。全基因BH完成后才选24基因进入后续阶段，避免对子集重新BH改变判断。

## Step3. 24基因的 worker 统计已跑通

[逐基因统计脚本](../scripts/R/reconstruct_hires_worker_statistics_20261011.R)保留全部120样本，依次完成：

1. 全局100次有放回 bootstrap，求表达系数中位数及非正系数比例；按旧规则与入口q做 Fisher 合并。
2. 按该基因 bulk 表达排序，同步排序比例。窗口60，候选分界30–90；对每个分界左右分别求 NNLS，取总残差平方和最小的位置。
3. 左右段各100次有放回重抽样，保存均值、标准差和差异Z检验。
4. 对可检测基因做50次随机参照。每次左段保留原始比例，右段使用各比例列分别打乱的参照；左右各5次重抽样。列打乱后不重新归一化行和。
5. 按旧版本的最近空分布位置规则生成经验p，并与Z检验 Fisher 合并。该规则不等同于一般的超越次数置换检验。

实测20,628次 NNLS，计算段约2秒；24个基因中21个达到可检测门槛，480个基因×类型组合中39个差异合并p<0.05。**这些是中间算法判定，不是39个已确认的生物学差异，更不是cell state。** 合并统计量彼此可能相关；本轮复现其数值规则，不额外声称合并p具有新验证的推断性质。

`worker_statistics_original_run1/worker_type_statistics.tsv` 可逐行核对，RDS保存分界搜索、重抽样系数和随机差异，便于下一步检查收缩与校准。

## Step4. 独立检查的实测结果

[Python检查脚本](../scripts/python/check_hires_statistics_and_input_fix_20261011.py)使用 SciPy 独立求解和分布函数；不把 R 实现自己当作答案。

| 检查 | 结果 |
|---|---|
| 已知两段表达生成值 | 正确找回预设分界，残差近零 |
| 原始输入的R与SciPy NNLS | 24基因全部通过，最大相对系数误差3.48×10⁻¹⁵ |
| 两段分界独立搜索 | 24个基因分界全部相同 |
| 完整基因解析p | 最大绝对差7.99×10⁻¹⁵ |
| 完整基因BH | 20类型全部通过，最大绝对差9.52×10⁻¹⁴ |
| Fisher与Z分布计算 | 最大绝对差低于3×10⁻¹⁵ |
| 官方研究文件完整性 | 本轮读取的原件哈希全部未变 |

检查记录在 `statistics_validation/validation_summary.json` 及相邻TSV。本轮没有验证官方随机数序列、经验空分布逐次等价或最终HiRes数值等价；数学函数核对通过不代表这些阶段也通过。

这是对上述仓库的限定调查，不能扩大成“整个GitHub都没有其他实现”。来源记录见 `public_repository_audit/`，对应只读脚本为[仓库清单](../scripts/python/inventory_public_cibersortx_repositories_20261011.py)和[官方接口定位](../scripts/python/inspect_ecotyper_public_interfaces_20261011.py)。

固定提交的重要接口行为：

- `pipeline/csx_hires_scheduler.R` 第22–39行：将比例与mixture列匹配，生成 `cibresults.txt` 和 `classes.txt`；按基因分块，各块保留全部样本。其每块入口BH是否与完整基因一次运行完全等同，应分别验证，不能预设一致。
- `pipeline/csx_hires_aggregate_worker_results.R` 第18–44行：查找每类型的HiRes输出，把NA替为1，再去掉跨样本恒定行并聚合。因此今后“原始表达/可靠性掩码”和“EcoTyper兼容导出”需要分开保存。
- 该聚合脚本还将最后一个 `raw_input` 排序，却写出 `all_input`，不能据此声称聚合行已排序。我们的未来导出将显式检查并排序聚合对象；本轮未修改官方脚本。
- `pipeline/state_discovery_presorted_filter_genes.R` 第23–77行：按基因合并各类型表达，按输入最小值选择log转换，再进行类型特异性筛选。兼容性包含数值尺度、基因名、样本列顺序和缺失语义，不能只把文件改名。

## Step6. 接下来具体补哪些阶段

| 流程阶段 | 当前状态 | 接下来验收什么 |
|---|---|---|
| 单细胞参考→signature | 原始数据抽样与官方矩阵已存在；独立建签名算法未实现 | 区分类别聚合、DE选择、300–500基因搜索与条件数选择，逐步比对官方中间文件 |
| signature→fractions | 目前使用官方固定比例；独立比例与S-mode未实现 | ν-SVR、标准化、非负截断与归一化、置换诊断、S-mode伪混合/ComBat/调整signature逐段核对 |
| 固定fractions→HiRes入口 | 全基因统计已完成，独立分布/求解检查通过 | 确认当前网页版输入及预处理范围，核对旧/新版本差异 |
| HiRes逐基因统计 | 冻结24基因已完成 | 对齐随机参照和统计过滤；先保存全部中间量 |
| 收缩、残差备用检验、弱变化重拟合 | 尚未实现 | 核对Spearman的ties/精确分支、平方权重、阈值及重新拟合的顺序 |
| 滑窗、OLS校准、稀有类型与最终过滤 | 滑窗核心已完成，其余未完成 | 数值幅度、排序恢复、1/NA掩码、恒定替换均需对照 |
| EcoTyper兼容导出与软件封装 | 只有入口规范和研究脚本 | 完整表达验证通过后再导出，不以核心矩阵代替最终G |

以原论文补充方法12.1–12.4为方法基准，以已合法取得的固定版本科学数值行为为版本参照，以Job24官方文件为小范围数值对照。当前网页版源码和线程随机流未知，所以暂不能承诺“与官方无明显差异”。先比较确定性阶段，再以同参数官方重复运行的差异作为随机阶段的参考范围；不要靠改变参数追逐某一次官方输出。

下一轮优先补收缩、残差备用检验和OLS，让冻结24基因形成完整下游路径；通过后再扩至120例全基因，最后补齐上游建signature和fractions。采用线性R研究脚本保存中间结果，算法稳定之后再考虑轻量命令行软件，避免现在加封装妨碍逐行审阅。

## Step7. 可复用入口与环境

本机实测 R4.4.1、nnls1.6及独立Python科学环境；每个R结果目录保存 `sessionInfo.txt`。新版[统计烟雾入口](../scripts/bash/run_hires_statistics_smoke_20261011.sh)依次运行完整基因入口、24基因核心和逐基因统计，显式接收原始完整mixture及24基因子集。Bash语法已检查；服务器环境和该入口在Linux的完整运行尚未实测。

在服务器已有连接中、已装有nnls的独立R环境，可用以下结构；路径需替换为实际上传目录：

```bash
bash "$PROJECT_DIR/scripts/bash/run_hires_statistics_smoke_20261011.sh" \
  "$PROJECT_DIR" "$BENCHMARK_DIR" "$ORIGINAL_MIXTURE" "$ORIGINAL_24GENES" "$NEW_OUTPUT_DIR"
```

第五轮核心入口现增加第四参数，必须显式提供24基因mixture；不再静默使用Adjusted导出。该修改仅影响未来调用，旧运行结果保留。当前入口不包含完整HiRes或EcoTyper运行，不能直接用于正式discovery/recovery。

本轮没有处理、修改或替代认证逻辑。继续通过独立科学数值实现推进；源码调查的完成度、接口兼容性和官方许可审批是不同问题。供应商二进制、反编译临时文件、源码缓存及大矩阵仍排除在Git发布范围外，独立脚本和证据摘要可供后续代码审阅。
