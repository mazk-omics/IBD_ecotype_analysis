## Step1. 本轮真正做成了什么

新增 [R 数值核心](../scripts/R/benchmark_hires_numeric_core_20261011.R)，使用公开的 [CRAN nnls 1.6](https://cran.r-project.org/package=nnls) 求解非负最小二乘。该包提供 Lawson–Hanson 算法接口，GPL ≥2；本轮没有复制供应商专有代码构建一个可执行文件。科学方法依据 [Newman et al. 2019](https://www.nature.com/articles/s41587-019-0114-2) Supplementary Note 1，章节 12.3；固定旧版本行为的证据见 [逐步对照](原论文与HiRes实现逐步对照.md)。

已实现的范围：

- 同一基因用全部样本的固定比例求 NNLS；系数是表达强度，不能归一化成细胞比例。
- 全局 100 次有放回重抽样及系数中位数；这是未过滤的中间量，不是完成的 group-mode。
- 按 bulk 表达排序，同步排列比例；每个滑窗做 5 次 bootstrap，取系数均值。
- 首尾补 W−1 行，前后矩阵平均，再恢复原样本顺序。
- 每基因保存 RDS 检查点，保留样本和类型标签；目标基因起止行可显式指定。尚无自动断点恢复或正式并行调度。

本轮选定24个基因来自既有冻结的共同100基因列表的等距位置，没有按预测表现重新挑选；覆盖20类原有参考类型，包含 DEFA6、APOA1、CA1、CHGA、NRXN1 等。仅检查这个小集合，不能推广成全基因表现。保留全120样本，不进行样本拆批。

## Step2. 实际结果与限制

输入来自同一个 Job24：`Weights`、`Mixture-Adjusted`、官方 group 和 HiRes。`Weights` 与该任务导出的 fraction 数值完全一致。调整后 mixture 有 **15,885×120** 数值，而 group 输出为 **17,040×20**；这已经提示预处理基因空间和导出回填需要单独追踪，不能直接把两者当成相同输入行集。

| 检查 | 本轮实测 |
|---|---|
| 小基准规模 | 24基因、120样本、20类型，窗口60 |
| 求解次数 | 9,744次 NNLS；所有已检查返回状态为正常 |
| 已知生成表达恢复 | 最大系数误差约 1.35×10⁻¹³ |
| R 对独立 SciPy 求解器 | 24基因全通过，最大相对系数误差约 5.95×10⁻¹⁵ |
| 真实基因最优性条件 | 非负性、对偶可行性、互补条件通过；缩放后的误差约10⁻¹⁶ |
| 固定比例矩阵 | 满列秩20，条件数约51.57；抽查滑窗的未重抽样矩阵均满秩 |
| 读取过的官方原件 | 本轮前后哈希一致 |
| 全局 bootstrap 中位数对官方 group | 每类型 log2(x+1) MAE 的中位数约0.905；尚非数值等价 |
| 官方 HiRes可比较范围 | 480个基因×类型组合中327个官方全样本非缺失，仅26个有样本变异 |

有变异的组合中，部分类型的原始滑窗趋势与官方结果相近，但小集合、少量可变行和恒定/NA过滤使总体相关性没有足够解释力。不能用相关性较高的几个类型宣称重构成功。数值幅度、NA/1 的可靠性语义和过滤规则仍明显不匹配；当前 `CORE_ONLY_*.tsv` 禁止用于正式 discovery/recovery。

本机计算段计时约0.78秒，完整 R 脚本进程约1.56秒；这些数值**只覆盖未校准核心**。它没有运行两段搜索、随机差异检验、筛选、收缩、回归校准和上游 S-mode。不能据此预测完整 HiRes 会在几分钟内跑完。

可追溯结果：`core_benchmark_run1/benchmark_summary.json`、`r_vs_scipy_nnls.tsv`、`real_gene_kkt_checks.tsv`、`core_vs_official_group.tsv`、`core_vs_official_hires.tsv`、`source_integrity_after_run.tsv`。输入来源和哈希位于 `core_benchmark_inputs/input_provenance.json`。所有矩阵均为新派生文件，未覆盖官方结果。

## Step3. 继续补齐的旧版本数值行为

本轮为 `randomizeInCols`、`getCol` 补齐成员 this/隐藏返回指针；为 `pspearman` 补齐 double 返回类型。新导出位于本机排除目录 `decompiled_numeric/CIBERSORTxHiRes_randomization_typed`。Ghidra 日志确认 `-readOnly` 丢弃修改，原 ELF 未改变。

**randomizeInCols 是每个细胞类型的比例列分别无放回打乱；不是让整张比例表共用一个样本排列。** 它保留每列的取值和均值，但破坏同一样本内的类型组合，行和可以不再等于1。不能在该随机参考步骤之后主动重新归一化行和，这会改变算法。R 性质检查另存 `column_randomization_contract.tsv`；它验证该操作的性质，不验证官方随机数逐次相等。

`pspearman` 在 n<1291 且没有 ties 时进入 `prho` 路径，其他情况进入 t 近似。结合已有 `spearmanCor` 调用，不能总把备用 p 值替换成 `cor.test(..., exact=FALSE)`。`prho`、ties及随机采样序列仍需进一步数值核对。

## Step4. 下一步按这个顺序完成，而不是直接放大全流程

1. **补齐固定120例的下游 HiRes。** 优先使用已经合法取得的调整后 mixture、fraction 和统计输出隔离测试：两段切点、Z/随机差异检验、Fisher、平方权重收缩、弱变化/稀有类型替换、OLS和最终NA/1处理。官方统计表只能在明确标注的中间量对照中复用，不能假装独立实现已经完成。
2. **追踪完整预处理和 BH 范围。** 查清17,040与15,885行的关系、Group/HiRes所用表达表、类型名和基因名回填、过滤开关及当前网页版本。原型目前没有对24基因单独做BH，避免错误地替代全基因多重检验。
3. **完成官方输出对照后再做120例全基因。** 冻结全部120样本、比例和全局统计，按目标基因分工；保存每基因检查点。检查已确认可估计的可变行，并分别记录未表达、缺乏证据和估计失败，不将NA填0以迎合EcoTyper。
4. **再补上游 fraction/S-mode，考虑2,025例。** 当前120例原型依赖官方已校正输入，不能拿它直接对2,025例声称走完官方规范路径。token 若获批，可切换回官方服务器实现并用同一基准比较；token 未获批时，继续独立科学实现，保持名称和方法说明清楚。

每次只增加一个算法阶段，再用同一冻结基准检查。完整独立实现完成前，不把它称为 CIBERSORTx、不混入原有 BayesPrism recovery 主结论。需要保留两个标签：方法描述对应论文的哪一段，以及数值实现对应哪个旧版本；不能将二者差异隐藏。

## Step5. 服务器算力与接口准备

新增 [服务器烟雾入口](../scripts/bash/run_hires_core_smoke_20261011.sh)，只调用两份独立 R 脚本，无 SSH、官方容器或 EcoTyper 命令。本轮未登录或在服务器安装环境。建议使用单独研究环境；本机已验证 R4.4.1 + nnls1.6，保存 `sessionInfo.txt`。服务器安装版本和完整依赖尚未实测，因此当前不提供伪造的服务器环境锁定记录。

将 R 脚本、bash入口和 `core_benchmark_inputs` 分开放到服务器相应位置，在已有连接中先激活装有 nnls 的独立 R 环境，然后运行：

未来若按17,040基因、2,025样本、20类型输出，单个未压缩 double 表达立方约 **5.52 GB（5.14 GiB）**，还不含工作副本、输入、元数据和文字文件。因此完整实现应逐基因/小目标块保存，固定全体样本，而非为加速任意拆样本。该规模按旧默认公式窗口为80，滑窗数1,946；仅每窗5次及全局100次已约1.68亿次NNLS，尚不含其余检验。完整耗时仍需服务器分阶段实测。
