# EcoTyper 下游代码规范

本文件补充 `Profile/CODE_STYLE.md`，只规定 EcoTyper 下游验证、统计和绘图脚本的具体做法。历史执行脚本保留原始字节哈希，GitHub 副本机械统一为 LF；新脚本和实质修改必须遵守以下约定。

## 研究脚本结构

- 文件开头用两三行中文说明目的、运行环境、输入和输出。
- 正文用 `# Step1.`、`# Step2.` 顺序展开，参数放在实际调用附近。
- 优先线性命令式代码；不为少量重复引入类、通用 pipeline 或配置框架。
- 循环只保留逐细胞类型、逐状态、逐图件或逐置换等算法必需部分。
- 关键中间对象使用 `shape`、`head()`、`table()`、`stopifnot()` 或 `assert` 就地核对，不打印完整大矩阵。

## 输入、缺失与统计

- 原始输入只读；运行前记录路径、尺寸和 SHA256，运行后复核哈希。
- 合并前分别检查 ID 唯一性、集合覆盖和顺序；不能依赖 pandas/R 的隐式排序。
- `Unassigned`、缺失谱系、不可评价状态和失败折显式保留，不能填 0 后参与均值或排名。
- 明确区分细胞、活检、样本、供者和患者统计单位；重复活检不能写成独立患者。
- P 值必须同时记录检验方向、置换次数、随机种子和校正族；Seurat 原生 Bonferroni 不改称 BH。
- 描述性重叠、相关或恢复 Z 不写成准确率、谱系真值或因果证据。

## 绘图

- 图只读取已验收结果表，不在绘图脚本中重新拟合模型或静默筛选样本。
- 每张图保存逐图 source data、显示顺序和样本注释。
- 默认导出 PDF、SVG 和 PNG；投稿栅格要求另行生成 TIFF，不能把 PNG 存在写成 TIFF 已完成。
- PDF/SVG 保留可编辑文字，字体不小于 5 pt；避免 rainbow/jet/hsv 色带。
- 缺失值显示为空白或专门颜色，不与数值 0 混淆。
- 网络边只按输入定义解释；共现边不能写成通讯、空间接触或因果关系。
- 最终 PDF 运行文字、碰撞和面板对齐检查，并保留机器审计与人工查看记录。

## 路径与历史脚本

- 新脚本优先从项目根目录或命令行参数解析路径，输出写入独立分析目录。
- 归档的上一轮脚本保留实际服务器绝对路径，是运行 provenance，不代表新代码可以继续硬编码个人路径。
- 历史执行环境的原始字节哈希与 GitHub LF 版本哈希分开保存；换行规范化不能写成算法或参数修改。
- 不在同一脚本中自动安装环境、下载数据并完成统计；环境准备、分析和验收分别记录。
- 带 `pilot`、旧版 `v2/v3` 或 superseded 标记的脚本只能用于追溯，不能作为默认入口。

## 最低验收

提交前至少完成：

```text
Python AST/py_compile 通过
R parse 通过（具备 R 时）
Bash -n 通过（具备 bash 时）
归档脚本 SHA256 与 manifest 一致
方法文档中的链接和入口文件存在
git diff --check 通过
```

若缺少运行数据或历史环境，只能报告“语法与归档核验通过”，不能声称完整重算通过。
